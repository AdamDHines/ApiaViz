# Two-command UV navigation study

30 September 2026. This is a fresh study, separate from the cancelled
`route-continuous-full` experiment and the paused `controller-full` study.
Neither historical study is resumed or modified.

## Run from the repository root

```sh
pixi run environments
pixi run trials
```

The first command creates three Blender scenes, exports spectral and collision
geometry, checks the teaching routes and releases, and renders UV/visible
previews. Inspect `apiaviz/output/uv-trials-v1/environments.html` afterwards.
The second command teaches all three models, runs **378 trials**, audits the
results, and creates `apiaviz/output/uv-trials-v1/report/index.html`.
It owns and stops its spectral renderer; no separate renderer command is needed.

Both commands show `tqdm` progress. Trial progress includes completed trials,
teaching views, movement iterations, simulated seconds, camera observations and
newly rendered positions. Figures and movie frames have their own progress bars.
The renderer uses the locked `scripts/uv_mitsuba/` Pixi environment. Blender must
be available on PATH or at `/Applications/Blender.app/Contents/MacOS/Blender`;
`pixi run environments --blender /path/to/blender` overrides detection.

## Parallel execution of the current study

The user started the full study and requested parallel execution on 30 September
2026. It was handed over from the serial coordinator to **six concurrent workers**
on the 14-core, 36 GiB Studio. The one completed trial was preserved; the
unfinished trial restarts from its initial state using its cached camera frames.
Do not start a second coordinator while this one owns the output lock.

The active coordinator writes `apiaviz/output/uv-trials-v1/parallel-console.log`.
To follow it in a terminal:

```sh
tail -f apiaviz/output/uv-trials-v1/parallel-console.log
```

`progress.json` records the coordinator PID, active worker count and execution
directory. That directory contains per-worker progress JSON and detailed logs.
To stop the background coordinator, send SIGTERM to the **current**
`coordinator_pid` from `progress.json`; it stops its owned workers and renderers
and preserves completed trials. Ctrl-C in `tail` stops only the log viewer.
After the coordinator has stopped, resume in the foreground with:

```sh
pixi run python -m apiaviz.research.uv_parallel --workers 6
```

Use `--output` for another prepared study. The original `pixi run trials` remains
the serial entry point: changing the task or scientific source would invalidate
the already frozen run. The added scheduler enforces all original source hashes
and records its own source snapshot/hash and assignments in a separate,
append-only execution manifest. Neither the protocol nor historical records are
rewritten to claim compatibility.

Each worker owns a world/seed/model batch, so checkpoints and trial files have
one writer. Per-pose file locks serialize competing camera cache misses; distinct
poses render concurrently. Teaching files are checked before reuse and written
under a lock. Each renderer and encoder keeps the original two-thread setting.
The root lock excludes competing coordinators, and worker failure stops the run
without converting system errors into navigation outcomes. Final audits,
statistics, figures and movies are generated by the coordinator after all jobs
finish, with the same selection and reporting rules.

All **142 tests pass**. A three-worker, six-trial fixture generated new camera
frames concurrently and reproduced the serial run's scientific results,
trajectories, movement events, decisions, sensor scores, teaching hashes and
model fingerprints exactly. Runtime, cache ownership and checkpoint file bytes
were excluded from this comparison. Wall times reflect concurrency and must not
be interpreted as isolated single-process model timings.
A separate three-worker interruption/resume check also completed all six trials
and passed the final audit. Compact evidence is recorded in
[parallel-validation.json](parallel-validation.json).

A live resource snapshot after handover showed approximately 11.3 CPU cores in
the six renderers, compared with about two cores previously, and roughly 7.5 GiB
summed resident memory for the coordinator, workers and render processes.
These are utilization measurements, not a measured whole-study speedup.

Ctrl-C preserves completed trials. Repeat the same command to resume; completed
trials and validated movies are skipped. Inputs, scene assets, checkpoints and
camera hashes are verified before reuse. Runtime errors stop the coordinator and
write `last-error.txt`, rather than becoming behavioral failure labels. See
`progress.json` for completion or interruption status.

The protocol freezes source, calibration, scene, teaching-image and checkpoint
hashes. After changing relevant source or configuration, use a fresh directory
for **both** commands, for example:

```sh
pixi run environments --output apiaviz/output/uv-trials-v2
pixi run trials --output apiaviz/output/uv-trials-v2
```

## Matrix and scientific inputs

| Factor | Values |
|---|---|
| Independently generated worlds | Meander, bend, hairpin; geometry seeds 20261001–20261003 |
| Wiring seeds | 19, 31, 43 |
| Scenarios | Aligned, left/right 50 cm release, left/right 40° heading error, left/right 50 cm kick |
| Initial search phases | +1, −1 |
| Models | ApiaViz + UV, Sobel + colour, Ardin-style |
| Trials | 3 × 3 × 7 × 2 × 3 = 378 |

All models share teaching positions and headings, acquisition geometry, the
mushroom-body learning rule, controller, camera-only avoidance, movement and
observation budgets, and evaluation. Each has 10,000 Kenyon cells: ApiaViz divides
these into 8,000 visible and 2,000 UV cells; each baseline has 10,000 visible cells.
The fixed front ends are untrained; downstream memory learns the teaching views.
This is a comparison with different sensory inputs and stream allocation, not
an isolated preprocessing or causal UV ablation. Equal cell counts do not imply
equal spike or computation costs; both are reported. Ardin-style is not claimed
to reproduce the original system exactly.

Blender supplies the geometry. Mitsuba performs CPU spectral transport over
320–700 nm using the archived honeybee responses and measured material proxies
from [UV calibration](../uv-calibration/README.md). Each panorama has six
co-registered bands: bee UV/blue/green and a separate visible RGB camera proxy.
ApiaViz receives raw linear bee responses through its
[UV processing stream](../uv-model-v1/README.md). Sobel and Ardin receive only the
visible image. Shared optical-flow avoidance also sees only that visible image.
Neither baseline is passed UV, including through false-colour conversions.

The visible camera is an explicitly analytical proxy: photon-weighted Gaussian
bands centred at 610/540/460 nm with widths 35/30/25 nm, unit-area normalization,
and zero sensitivity at and below 400 nm. Its fixed response is
`RGB = linear / (linear + 1)`, with no per-image adaptation or gamma transform.
It is not an empirically calibrated RGB camera or an exact reproduction of the
historical Blender RGB input. Illumination remains a modeled sky/sun, material
curves are proxies, and UV polarization is disabled. No absolute photon-catch
claim is made. Preview/movie UV false colours are for display only.

Full runs render 480 × 144 panoramas at 64 samples per pixel and sample the common
199 × 51 retina. Raw six-band float arrays are retained losslessly in compressed
NPZ files with pose, seed, version and checksum sidecars. One uncompressed frame
is about 1.66 MB; compression varies by view, and the summary records actual cache
bytes. Identical positions reuse panoramas across headings and models. Total
runtime and storage depend on trajectories; progress estimates are not a
full-study throughput guarantee.

## Collision handling and accounting

The evaluator uses swept projections of the actual rock meshes with a 5 mm body
radius, not oversized circular rock bounds. Unsafe walking is rejected and the
navigator continues until arrival or its normal budget/visual termination.
Blocked proposals and visual decisions are recorded; commanded movement and
camera/time costs still count. Field boundaries use the same nonterminal block
behavior. Releases and external kicks apply only a safe swept prefix, or are
skipped if there is no clearance. Requested and applied doses are retained.

Geometry, contact signals, route coordinates and nest bearing do not enter the
policies. Learned memory persists through avoidance and kicks, without route
snap-back or controller resets. See the
[navigation safeguards](../navigation-safety-v1/README.md) for geometry limits,
regression evidence and remaining behavioral failures. Blocking prevents illegal
placement; it does not guarantee successful visual navigation.

Full trials allow 360 simulated seconds, 2,600 observations and 200 movement
iterations; kicks are scheduled before iteration 36. Every completed trial is
checked for swept body clearance, placement, time/view/movement accounting,
preserved model/memory state and absence of resets before its result is committed
to the output directory. Partial runs remain explicitly partial.

## Outputs

The HTML report includes all outcomes, all trajectories, arrival heatmaps,
termination counts, and costs. CSV and JSON retain trial-level results; PNG/SVG
figures and a multipage PDF support export. Statistics include recovery with its
applicable denominator, route deviation, blocked movement, applied perturbation
doses, observations, simulated time, encoding time and active KC spikes.
Full/shortened/skipped/unattempted perturbations are separated, with a secondary
whole-paired-block full-dose sensitivity analysis.

Arrival differences are paired by world/seed/scenario, averaging search phases;
descriptive bootstrap intervals resample worlds. Three synthetic worlds from one
habitat family do not justify strong population significance claims. Wiring
seeds, phases and stations are not independent environments. Wall time includes
cache misses and depends on method order, so separate encoding costs and render
counts are also provided. Every failure stays in the primary denominator.

Movies show the acquired visible camera, a labelled UV false-colour panel,
overhead trace, familiarity, blocked commands and outcome. Kicks break the walked
trajectory line. Selection is fixed: first wiring seed, positive phase, aligned
and kick-right cases across all worlds/models (18 movies), plus the first
scheduled failure per world/model if not already included (up to 27 total).
There is no selection of best outcomes. Playback is accelerated, with held camera
samples between acquisitions and an enlarged ant marker.

For a partial report without running further trials:

```sh
pixi run python -m apiaviz.research.uv_trials report --output apiaviz/output/uv-trials-v1
```

## Bounded verification

Only small development fixtures were run during initial implementation. The user
subsequently started the 378-trial study; its parallel handover is documented
above. To prepare a separate six-trial smoke fixture:

```sh
pixi run environments --smoke
pixi run trials --smoke
```

This uses `apiaviz/output/uv-trials-smoke-v1`, one small world, one wiring seed,
one phase, aligned/kick-right scenarios and all three models. Four movement
iterations, a 60-second ceiling and four samples per pixel keep this a software
integration check. Its outcomes are not comparative navigation evidence.

The implementation check used a separately named local directory:

```sh
pixi run --locked test
pixi run environments --smoke --output apiaviz/output/uv-trials-pipeline-check-v3
pixi run trials --output apiaviz/output/uv-trials-pipeline-check-v3
pixi run --manifest-path scripts/uv_mitsuba/pixi.toml python scripts/uv_mitsuba/validate_trial_camera.py --environment apiaviz/output/uv-trials-pipeline-check-v3/worlds/meander --output /private/tmp/apiaviz-six-band-validation-final.json
```

All 139 tests pass. The six closed-loop smoke trials exercise walking and all
three scheduled kicks, and pass physics/accounting audits. All reach the
deliberately short movement budget. Interrupting after one completed trial and
resuming preserves that result and runs the remaining five. Numeric spectral
checks compare the actual six-channel renderer against wavelength quadrature;
UV-only illumination produces exactly zero in all three visible channels.
Re-running the completed command preserves all six trial and movie hashes.
All six H.264 movies decode successfully; both HTML pages have valid local
links, and all 26 report artifacts match their manifest. This smoke fixture
does not generate blocked contacts; those are covered by dedicated collision
regressions and the earlier 240-placement mesh audit.

Passing camera position as a runtime parameter avoids recompiling a shader per
pose. A three-pose fixture comparison with distinct per-position seeds produced
identical images (maximum absolute difference zero); warm renders were about
0.54 s with literal positions versus 0.02 s with runtime positions. This tiny
fixture is not a forecast of full-scene performance. Compact evidence is in
[validation.json](validation.json); full frames, scenes and movies remain local
under the ignored output directory.
